## 요청과 승인 범위

현재 만든 로우폴리 모델을 활용해 캐릭터가 실제로 건설·운반·생산·생활하는 모습을 보여 주세요. 작업 진행 막대만 움직이는 것이 아니라, 캐릭터의 자세와 도구, 시설의 움직임, 물건의 위치 변화가 실제 작업과 일치해야 합니다.

- **2026-10-17 사용자 캐릭터 전환 요청 반영:** 첨부 시트처럼 두 팔·두 다리로 이동하고 손으로 도구를 사용하는 캐릭터를 기준으로 합니다. 기존 개미 직립 허용안은 대체되었습니다. 여섯 외형의 종족·능력 차이는 확정하지 않습니다.
- 두 발 보행에서 운반·앉기·숙이기·작업 자세로 전환합니다. 큰 머리와 짧은 팔의 도달 범위를 기준으로 작업 높이를 확인합니다. 머리 돌기·귀·잎은 외형 요소이며 감각 기관이나 작업용 추가 팔다리로 가정하지 않습니다.
- 기존 개미 작업 클립 17개는 제작되어 있으나 새 캐릭터에 호환되는 클립은 아닙니다. 새 메시·본·웨이트를 확인한 뒤 재제작 또는 리타게팅 가능 여부를 판단합니다. 자세한 변경 기준은 `docs/CHARACTER_TRANSITION_SPEC.md`를 따릅니다.
- 이 문서는 **애니메이션 구현 요청안**입니다. 아래 세부 동작과 타이밍은 구현용 제안이며 기존 확정 게임 규칙을 새로 정하거나 바꾸지 않습니다. 실제 코드·기획과 충돌하면 게임 규칙을 유지하고 연출을 맞추세요.
- 자동 작업, 생산량, 수술 결과, 재료 소비 시점, 전투 피해, 문 통행 정책 등은 기존 게임 로직을 사용합니다. 없는 시스템을 연출을 이유로 새로 만들지 마세요.

## 공통 연출 규칙

### 자세와 공통 클립

| 클립 역할 | 보여 줄 동작 |
|---|---|
| Idle / Walk | 새 캐릭터의 두 발 대기·보행. 기존 이동 로직은 유지하고 얼굴과 머리는 작은 범위로 움직임 |
| StandEnter / StandExit | 두 발 보행 자세에서 작업 자세로 정렬 / 종료 후 보행 자세로 복귀. 앉거나 숙인 작업은 해당 높이에 맞춤 |
| Pickup / Carry / PutDown | 몸을 숙여 집기 → 손이나 등에 부착해 운반 → 내려놓고 손을 뗌 |
| GroundWork | 낮게 숙여 손으로 흙 파기·작물 손질. 반복 박자에 작은 변주 |
| BenchWork | 직립해서 손으로 누르기·자르기·섞기. 시설별 도구와 손 궤적 변경 |
| Hammer / Chop / Mine | 도구 들기 → 대상 접촉 → 반동. 실제 접촉 위치에 효과 발생 |
| Treat / Operate | 환자 쪽으로 숙이거나 직립해 처치. 일반 처치와 수술은 동작·도구로 구분 |
| Eat / Sit / Rest / Sleep | 음식 집기·턱 움직임 / 자리 앉기 / 가벼운 휴식 / 몸과 다리를 접고 수면 |
| Mourn / Inspect | 묘비 앞에 잠깐 고개 숙이기 / 시설을 살펴보는 시선과 손 움직임 |

공통 클립을 재사용하되 모든 작업을 동일한 손 흔들기로 표현하지 마세요. 새 캐릭터의 두 팔·두 다리와 얼굴 표현을 기준으로 본·웨이트를 준비합니다. Humanoid 또는 Generic 선택은 실제 본 구조와 필요한 변형을 보고 결정하며, 6족 개미 리그를 그대로 적용하거나 자동 호환으로 간주하지 않습니다. 기존 개미 원본은 보존합니다. 시설별 도구·높이·목표 위치로 동작을 구분하고 임시 몸통 흔들기만 연결한 상태를 완료로 표시하지 마세요.

권장 초기값: 자세 전환 0.2~0.4초, 집기·내려놓기 0.4~0.8초, 작업 루프 0.8~1.6초. 모두 조정 가능한 **연출 제안값**이며 작업 소요시간은 바꾸지 않습니다. 빠른 장수는 무조건 클립 전체를 과속하기보다 실제 진행률에 맞춰 루프 횟수와 동작 속도를 적절히 조정합니다.

### 시설마다 필요한 지점

- `WorkPoint_*`: 캐릭터가 서는 접근 가능한 자리와 바라볼 방향.
- `HandTarget_*`, `ToolContact_*`: 손·도구가 닿는 실제 위치. 필요할 때만 추가.
- `InputPoint`, `OutputPoint`: 재료를 놓거나 완성품이 나타나는 위치.
- `SeatPoint`, `PatientPoint`, `CarryAnchor`: 해당 기능이 있는 경우에만 사용.
- 회전 부품은 피벗 기준으로 움직입니다. 기존 `Gate_Hinge`, `Door_Hinge`, `Lid_Hinge`, `GateLeft_Hinge`, `GateRight_Hinge`, `Turret_Pivot`를 확인하고 활용하세요. Blender가 이름 뒤에 숫자를 붙였을 수 있으므로 이름 문자열 전역 검색보다 prefab의 직렬화 참조를 우선합니다.
- 여러 장수가 작업 가능한 경우 자리마다 예약을 둬 같은 점에 겹쳐 서지 않게 합니다. 작업대 정면이 막혔으면 내부나 벽 너머에서 작업하는 연출로 우회하지 않습니다.

### 실제 작업과 동기화

`이동 → 자리 확보·방향 정렬 → 자세 전환 → 작업 반복 → 실제 결과 반영 → 자세 복귀·이동` 순서로 표현합니다.

게임 작업 상태가 최종 기준입니다. 애니메이션 이벤트는 타격음·파편·손에서 물건 놓기 등의 표현에 사용하고, 이벤트가 여러 번 재생되거나 생략됐다는 이유로 자원·피해·치료 결과가 중복 적용되지 않게 합니다. 실제 인벤토리 전달과 표시용 운반물 부착/해제도 각각 한 번만 처리합니다.

- 재료 부족·전력 부족·작업 정지: 실제 진행이 멈추면 작업 동작과 효과도 멈춤. 기존 대기/이탈 규칙 준수.
- 취소·대상 철거·사망·쓰러짐·작업 교체: 자리 예약, 도구, IK 목표, 운반 표시물 정리. 자원 환급·유실은 기존 규칙대로.
- 일시정지 및 배속: 캐릭터, 시설, 파티클, 작업음이 게임 시간 기준으로 동작. 실시간 타이머로 작업 완료 처리 금지.
- 저장/불러오기: 영구 상태와 실제 작업에서 표현을 복구. 순간 타격·완료 효과를 재생해 결과를 다시 지급하지 않음.
- 카메라 밖: 시각 갱신을 줄여도 실제 작업은 유지. 화면에 돌아오면 올바른 작업 자세·상태로 복구.
- 이동 위치는 기존 이동 시스템이 관리. Root Motion을 사용할 경우 NavMesh/이동 코드와 이중 이동하지 않는 구조를 먼저 검증.

## 시설별 구체 연출

### 1. 정착지·건설·운반·보관

| 대상 모델 | 캐릭터 동작 | 시설·물건 반응 / 주의사항 |
|---|---|---|
| `CC_NestEntrance` | 입구 경사 쪽으로 이동하고 진입 방향으로 머리 숙임 | 실제 출입 로직이 있을 때만 입구 안으로 이동·가림 처리. 입구 앞에서 갑자기 사라지거나 새 순간이동 규칙을 만들지 않음 |
| `CC_ConstructionPlan` | 자재를 운반해 경계 안의 지정 지점에 내려놓음 | 도착한 실제 재료에 대응하는 자재 표시. 예약만 된 재료를 이미 도착한 것처럼 표시하지 않음 |
| `CC_ConstructionFrame` | 두 발로 서서 망치질·기둥 조립, 낮은 부분은 숙여 작업 | 실제 공사 진행률에 따라 골조→부분 완성→최종 모델. 골조 모델은 공통 중간 단계용이며 시설별 최종 모델로 교체. 시작부터 완성 건물이 나타나지 않음 |
| `CC_DemolitionRubble` | 철거 대상에 도구질, 마지막에 물러남 | 실제 철거 완료 시 건물 제거 및 잔해/반환 자원 표시. 무조건 파괴·반환으로 처리하지 않고 기존 철거 규칙 적용 |
| `CC_Storage` | 입구의 보관 지점에 물건 놓기·꺼내기 | 실제 재고를 요약하는 적재물 표시. 물건마다 무한히 메시를 쌓지 않고 품목별 대표 묶음 사용. 허용 해제·비우기 시 기존 로직으로 바닥에 떨어지는 물건 표시 |
| `CC_Refrigerator` | 손잡이를 향해 손 뻗기 → 물건 출입 → 손 떼기 | 문을 피벗으로 열고 닫음. 다른 사용자가 사용 중일 때 닫지 않음. 내부 선반을 활용하고 재고는 별도 표시. 정전·냉기 감소는 실제 상태에 맞춘 약한 표시 |
| `CC_Freezer` | 뚜껑 들기 → 몸 숙여 물건 출입 → 닫기 | `Lid_Hinge` 회전. 뚜껑·손이 관통하지 않게 하고 표시물은 실제 재고와 일치 |
| 모든 운반 물품 | 집는 순간 손 또는 등 앵커에 표시물 부착, 이동 후 내려놓음 | 실제 바닥 물건과 손에 든 표시물이 동시에 복제돼 보이지 않도록 동기화. 건물 내부에 들어간 재고는 운반 애니메이션만으로 재이동시키지 않음 |

건설 중간 모델 전환 비율은 연출용으로 조정하되 공사 시작·재료 소비·공사 중단·완료 판정은 그대로 유지합니다. 초기안은 0~30% 기초, 30~80% 골조, 80~100% 마감 표현으로 시작할 수 있습니다.

## 구현 순서와 완료 기준

1. 새 캐릭터 모델·본과 기존 Animator·작업 시스템을 조사하고 수정 파일 소유권을 공동 보드에 기록합니다. 기존 사용 중 자산을 덮어쓰지 말고 표시용 자식 계층을 분리합니다.
2. **운반·건설·농사**를 먼저 실제 작업으로 연결합니다. 한 장수가 재료를 집고, 걷고, 놓고, 현장에서 작업하며 결과물이 생기는 흐름을 검증합니다.
3. 공통 작업 자세·도구 앵커를 바탕으로 생산·의료·생활을 연결합니다.
4. 문·냉각 보관·전력·방어 기구의 자체 움직임과 효과를 실제 상태에 연결합니다.
5. 없는 게임 시스템은 미연결 목록으로 명시합니다. 개별 시설에 임시 타이머만 붙여 상호작용 구현 완료라고 보고하지 마세요.

필수 확인:

- 새 캐릭터로 접촉 위치·높이·직립 자세·발 미끄러짐·관통 여부 확인. 가구 크기를 맞추더라도 기존 게임 판정 영역을 무단 변경하지 않음.
- 같은 시설을 여러 장수가 사용하거나 작업을 인계할 때 자리·도구·재료 표시 중복 없음.
- 도착 전 작업 동작 없음. 실제 진행 중에만 작업 루프. 완료 시 결과 표시 정확히 한 번.
- 일시정지·배속·취소·대상 철거·장수 쓰러짐·작업 변경 시 정상 중단과 정리.
- 자원 부족·전력 부족·접근 불가·수술 실패 등에서 성공 연출을 재생하지 않음.
- 저장 왕복 후 물건 복제·약품 중복 소비·완료 보상 재지급 없음.
- 멀리서도 작업 종류가 구분되며, 많은 장수가 동시에 일할 때 메시/파티클/실시간 그림자 비용이 과도하지 않음. 화면 밖 시각 최적화가 시뮬레이션을 멈추지 않음.
