# S2 인계 — 단기 목표 사슬·달성 순간

기존 StartGuide·BetaProgress·CampaignNextSteps를 하나의 목표 사슬로 연결했다. ONI의 생존→안정→확장, Factorio 연구 완료, Frostpunk 목표 달성 피드백을 기존 HUD·토스트에 적용했다. 새 시스템 창·자원·자동 결정은 추가하지 않았다. 추천 결정은 [DECISIONS_1101_S2.md](DECISIONS_1101_S2.md)에 사용자 미확인으로 기록했다.

## 수정 파일

- `Assets/_Project/Scripts/UI/StartGuide.cs`: 별도 체크리스트 대신 목표 사슬 호환 진입점.
- `UI/BetaProgress.cs`: 기존 Objective 패널에서 상시 현재 목표·진행·행동·이후 가능한 일, 달성 강조. firstHints와 분리.
- `UI/CampaignNextSteps.cs`: 같은 목표 캐시, 위독·원정 이동·귀환 맥락과 기존 시대별 병행 준비 유지.
- `UI/ToastManager.cs`: Achievement 스타일(15px 굵게·기존 accent), 기존 위험/경고 우선. 화면에 처음 보이기 전 만료하지 않음.
- 신규 `UI/GoalChain.cs`, `UI/GoalChain.Progress.cs`: 달성 사실 보존·목표 순서·현재 상태 진행/막힘·실제 기존 해금 안내. `.meta`는 Claude Unity 반입 시 생성 확인.
- `Save/SaveDtos.cs`, `SaveSnapshot.cs`, `SavePreflight.cs`: 선택 상태 추가, 복사 캡처/복원, 잘못된 비트 거부. 기존 저장 버전 유지.
- `AgentScripts/Review1101S2Checks.cs`: 오프라인 Main, Claude 전용 RunScene.
- `docs/IMPLEMENTATION_BOARD.md`, 이 문서, S2 결정 문서.

이 worktree는 시작부터 다수 수정/미추적 파일을 포함했다. 특히 BetaProgress와 CampaignNextSteps에는 Q2 선행 작업이 있었다. 전체 git diff를 S2 변경으로 취급하지 말고 위 파일의 S2 연결만 병합할 것. 원본은 읽기만 했다.

## 잠정 수치·저장

- 기존 식량 20·침대 부족0 재사용. 새 경제 수치 없음.
- 갱신 0.5초, HUD 달성 강조 4초, 토스트 글자 15px(기존 본문13px). 토스트 수명은 기존 설정 재사용.
- 16단계는 화면 체크리스트로 늘어놓지 않는다. 항상 가장 앞의 미완료 목표 하나만 표시한다.
- `goalChain.completed`는 16비트 완료 사실, `initialized`는 첫 이관/새 판 초기 관찰 여부. 소비·시설 파괴 이후에도 이미 달성한 단계는 유지.
- 구저장 null/기본 상태는 완료 알림 없이 현재 사실로 시작한다. 연구소2등급 이상은 초반4단계 안내를 생략한다. 과거 원정을 증명할 보스 기록/현재 이동이 없으면 첫 원정 안내가 다시 나올 수 있다.
- 상위 목표를 먼저 달성해도 기억한다. 최종 발사 완료는 전체 사슬 종료. 안내가 연구·출정·발사 실행 조건을 바꾸지 않는다.

## 검증

- 지정 `offc.sh`는 worktree에 없는 외부 에셋 `SpinFree` 때문에 단독 실행 시 CS0246 1건. 기존 Q2 컴파일 보완 방식으로 원본의 누락된 외부 소스43개를 로컬 응답 파일에 읽기 전용 추가한 전체 게임 컴파일 **오류 0**.
- S2 검사 컴파일 오류 0, `Review1101S2Checks.Main` **59 검사 통과**. 순서 밖 성취·미완료 목표 선택, 마스크/구저장 경계, 단계 연결을 검증했다. `Temp/off/CompileS2.ps1 -OfflineChecks`와 `Temp/off/verification.txt`에 재현 경로/결과가 있다.
- Unity 실행·실제 UI·전체 저장 왕복·RunScene은 미실행. 오프라인 성공을 화면/실플레이 통과로 해석하지 말 것.
- Graphify query 사용. 최신 담당 파일 밖 수정 금지에 따라 graphify-out 갱신은 병합 담당에게 인계한다.
- 커밋·prefab·SAVE 일지·캡처·Notion 기록 없음. 카카오 완료 알림 도구는 현재 세션에 없어 전송하지 못했다.

## Claude 화면 확인 요청

1. 새 게임에서 firstHints를 꺼도 현재 목표 하나가 남는지, 잔해 회수 후 생활 안정→첫 연구로 즉시 이어지는지 확인.
2. 연구 정지/재개·담당 없음·표본 연구·승급 선행/재고 부족에서 진행과 할 일 문구를 확인. 완료 시 큰 토스트·HUD 4초 강조·다음 목표가 함께 보이는지 확인. 기존 연구 완료 알림과 겹칠 때 과밀 여부 확인.
3. 첫 원정→A 반입→산업→B/C→미래→D 반입 순서를 확인. 먼저 달성한 목표가 나중에 다시 요구되지 않는지 확인.
4. 위독자·원정 이동 상태에서 목표 제목은 유지되고 행동 줄만 바뀌는지 확인. 여러 원정이 있으면 기존처럼 첫 발견 수송수단을 안내한다.
5. 로켓 조립→수동 가동·15일 방어→직접 탑승·발사 흐름을 확인. 발사대 파괴·부품 미완성·연료 미적재·가동 대기에서는 해당 막힘과 복구 행동이 보이는지 확인(목표 달성 사실은 유지).
6. 1920×1080·1280×720에서 기존 좌측 HUD/원정 미니맵과 겹침, 긴 재고·탐지 문구 줄바꿈, 토스트 잘림을 실제 화면으로 확인. 패널은 본문 preferredHeight에 따라 높이를 맞춘다. 캡처는 SAVE 때만.
7. `RunScene` 실행 후 실제 저장→불러오기, 구저장, 새 게임 재시작을 확인. 달성 상태 유지·이전 판 상태 제거·완료 알림 재생 없음 확인. RunScene은 연구/목표 상태를 finally에서 복원하지만 검사 중 생성된 완료 토스트는 정상 수명 뒤 사라진다.

다른 담당 파일 변경 요청: 코드 연결을 위한 필수 추가 수정 없음. 병합 후 Graphify 갱신·실제 화면/저장 검증만 필요하다.
