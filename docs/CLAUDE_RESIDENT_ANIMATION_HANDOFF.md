# Claude Code 요청 — 조합형 캐릭터와 가구 작업 애니메이션 분리

## 요청 목적과 가장 중요한 정정

기존 개미 대신 새로 만든 통통하고 귀여운 캐릭터가 시설에서 일하도록 모델·애니메이션 자산을 완성해 주세요.

**가구마다 특정 캐릭터를 붙여서 납품하면 안 됩니다.** 실제 캐릭터는 외형 부품을 조합해 다양하게 생성될 예정입니다. 어떤 외형의 캐릭터든 공통 동작을 재생하고 어느 가구에서든 작업할 수 있어야 합니다.

가구 앞에 캐릭터를 배치한 장면은 작업 연출을 확인하는 미리보기로만 유지하세요. 실제 사용 자산은 가구, 캐릭터 부품, 공통 리그, 애니메이션, 도구를 분리합니다. 현재 단계에서 랜덤 생성 시스템이나 Unity 게임 기능까지 만들라는 요청은 아닙니다.

## 작업 범위

- Blender 모델·리깅·애니메이션과 적용 설명, 재사용 가능한 내보내기 파일을 정리합니다.
- 원본 개미 모델과 기존 시설 파일은 보존합니다. 새 주민용 미리보기에서는 개미를 사용하지 않습니다.
- 캐릭터 디자인을 다시 바꾸지 않습니다. 현재 귀여운 외형, 표정·머리·흉터·부상 부품을 재사용합니다.
- Unity 씬·게임 코드·HUD는 이번 요청 범위에서 수정하지 않습니다.
- 프로젝트 AGENTS.md, log.md와 담당 보드를 먼저 확인하세요. 다른 작업자의 파일과 충돌하지 않도록 담당을 표시하세요.
- 이 요청서는 SAVE 요청이 아닙니다. 개발 일지, Notion 일지, 커밋·push는 별도 SAVE 절차를 임의로 실행하지 마세요.

## 실제로 만들어진 내용과 검증 범위

- `Resident_Animation_Library`: 대표 리그 `ResidentRig_01`, `Resident|이름` 형식의 공통 Action.
- `Resident_24_Rigged`: 외형 24종이 동일한 뼈 이름을 사용하는 리그.
- `Work__CC_*`: 시설별 미리보기 장면 79개. 모든 시설에 배우가 필요한 것은 아닙니다.
- 뼈 12개: Root, Body, Head, Arm.L/R, Hand.L/R, Foot.L/R, Ear.L/R, Tail.
- 캐릭터 정면은 로컬 -Y, 24fps. Humanoid가 아닌 Generic 방식입니다.
- 동작: Idle, Walk, Run, StandEnter, StandExit, StandIdle, Pickup, PutDown, Carry, GroundWork, BenchWork, Hammer, Chop, Mine, Treat, Operate, Stir, Grind, Saw, Stamp, Wash, Eat, Sit, Rest, Sleep, Mourn, Inspect, Attack, Hurt, Death.
- 구조 검사 결과: Action 30개, 곡선 2,160개, 리그 101개(미리보기 복제 포함), 가중치 메시 3,497개, 시설 장면 79개, 보고된 오류 0개.
- **이는 최종 품질 통과가 아닙니다.** 모든 시설의 손·도구 접촉, 모든 조합, FBX 왕복 및 Unity 재생은 검증하지 않았습니다.
- 대표 대기·걷기·망치·주방·침상 옆 치료·매트 수면을 일부 프레임으로 확인했습니다. 작업대에서 손과 도구의 겹침이 보여 손 위치와 팔 연결을 보완했지만 정밀 접촉은 추가 검수해야 합니다.
- 수면 매트 배우의 눈을 감기는 보정은 해당 미리보기 메시에서만 했습니다. 공통 표정 전환 애니메이션은 아닙니다.

## 우선 수정 1 — 실제 자산과 미리보기 분리

1. **시설 자산:** 주민 메시·주민 리그·주민 Action을 포함하지 않습니다. 시설 자체의 문·뚜껑·경첩 애니메이션은 유지합니다.
2. **캐릭터 자산:** 외형 부품과 공통 뼈대. 특정 시설이나 그 시설의 월드 위치에 종속되지 않습니다.
3. **동작 자산:** 외형과 시설에 관계없이 공통 리그에서 재생합니다. 시설 앞 좌표를 캐릭터 Action에 구워 넣지 않습니다.
4. **도구 자산:** 손 소켓에 붙이는 별도 모델. 망치·곡괭이 등이 피부와 합쳐진 캐릭터 메시가 되지 않게 합니다.
5. **미리보기 파일:** 시설 + 임의 조합 캐릭터 + 도구를 조립한 검수용 장면. 실제 사용 파일과 명확히 구분합니다.

원하는 결과 파일 이름은 자유지만, 시설 전용 / 캐릭터·부품 전용 / 공통 동작 / 미리보기를 사용자가 구별할 수 있어야 합니다. 기존 작업본을 덮어써 원본을 잃지 않도록 하세요.

## 우선 수정 2 — 조합 가능한 부품 규격

- 몸통, 귀, 머리 장식, 얼굴 표정, 색상·무늬, 흉터·부상, 의복·장비를 현재 부품에서 정리합니다.
- 부품별 원점·축·스케일·부착 뼈·가중치 기준을 통일합니다.
- 서로 다른 귀나 머리 부품으로 교체해도 눈·입·손·도구 위치가 깨지지 않게 합니다.
- 24개 고정 캐릭터를 만드는 데서 끝내지 말고, 서로 다른 원본의 부품을 섞은 몇 가지 수동 조합으로 공통 동작 재생을 검증하세요. **자동 랜덤 생성 코드는 만들지 않습니다.**
- 기존 표정 및 흉터·부상은 별도 부품이라는 기획을 유지합니다. 상처를 표정으로 취급하지 않습니다.
- 잠듦·사망처럼 동작과 얼굴 상태가 맞아야 하는 경우, 어떤 표정 부품을 사용해야 하는지 연결 기준을 적고 미리보기에서도 맞춰 주세요.

## 우선 수정 3 — 시설 크기와 작업 위치

사용자가 지적한 문제: “가구가 너무 작으면 클릭하기 어렵다.”

- 캐릭터와 가구 크기를 자연스럽게 맞춥니다. 작업면이 손 위치와 맞고, 큰 머리가 시설 전체를 가리지 않아야 합니다.
- 현재 미리보기는 테이블류 XY를 약 1.30/1.25, Z를 0.80으로, 침대류 XY를 약 1.55/1.45로 보정했습니다. 임시값이며 전체 시설의 최종 규격으로 확정된 것은 아닙니다.
- 작업 위치뿐 아니라 캐릭터가 바라볼 방향, 손의 작업 목표 위치, 도구 접촉점, 운반·입출력 위치를 시설 로컬 좌표로 명확히 합니다.
- 스케일 변경 후 기존 작업 지점 JSON이 그대로 남아 있으면 실제 위치와 어긋납니다. 최종 내보낸 모델 기준으로 좌표·단위·배율을 일치시키세요.
- 클릭 영역은 가구 전체 외곽을 기준으로 잡는 방향을 설명서에 제안할 수 있지만 **Unity 선택 기능은 이번 작업에서 구현하지 않습니다.**

## 현재 코드의 주의점 / 반드시 확인할 항목

- `build.py`와 `facilities.py`는 새 장면·데이터를 만드는 스크립트입니다. 현재 파일에서 무조건 재실행하면 중복 이름과 장면이 생길 수 있습니다.
- `tune.py`는 도구 메시 정점에 회전을 추가합니다. 반복 실행 시 누적될 수 있으므로 그대로 반복 실행하지 마세요.
- 라이브 파일에서 직접 보정한 내용과 생성 코드 사이에 차이가 남아 있을 수 있습니다. 특히 손의 높이·전방 이동, 카메라 방향, 수면 눈 보정. 저장된 작업본을 먼저 확인하고 재생성 경로를 정리하세요.
- `reach.py`의 팔 연결 메시 추가와 손 전방 보정은 별도 후처리입니다. 완성 리그 제작 절차에서 빠지지 않게 하세요.
- 현재 `rig.py`의 ToolGrip/CarryAnchor Empty는 뼈 위치를 복사하고 별도 위치 힌트를 저장하는 형태입니다. 힌트가 실제 부착 오프셋으로 적용되는지 검증하고, 실제 재사용 가능한 소켓으로 정리하세요.
- 현재 미리보기 도구는 손 뼈에 가중치를 줘 움직입니다. 최종 재사용 자산에서는 별도 도구·소켓 조립 방식으로 정리하세요.
- Carry 미리보기는 시설/물건 루트를 배우 Body 뼈에 연결합니다. 이를 시설 전용 파일에 그대로 내보내지 마세요.
- 동작별 `VisualContact` 마커는 시각적 타이밍 참고용입니다. 자원 지급·대미지·치료 완료 이벤트가 구현된 것이 아닙니다.
- 일부 시설의 문·뚜껑 동작 길이와 주민 동작 길이가 다를 수 있습니다. 미리보기에서 시설 동작이 잘리지 않는지 확인하세요.
- `CC_CommanderBed` 현재 미리보기는 침대 옆 Treat입니다. 이를 수면 장면이라고 오인하지 마세요. 실제 Sleep 미리보기는 `CC_SleepingMat`입니다.
- FBX는 내보내기만 성공했습니다. 본 이름·축·루프·메시 바인딩이 보존되는지 새 검수 장면으로 재임포트해 확인해야 합니다.

## 완료 기준

- 시설 전용 파일을 열면 주민이 없고, 캐릭터 전용 파일을 열면 시설이 없습니다.
- 서로 다른 외형 부품을 섞은 수동 조합 여러 개가 동일한 공통 동작을 정상 재생합니다.
- 같은 시설에서 캐릭터 외형만 바꿔도 작업 위치·손·도구가 유지됩니다.
- 도구가 손에서 떨어지거나 얼굴을 크게 관통하지 않습니다. 발·침대·의자와의 심한 관통도 수정합니다.
- 기본 이동/대기, 운반/줍기, 작업대/채집/채굴, 치료, 식사/휴식/수면, 전투/피격/사망을 움직이는 미리보기로 확인할 수 있습니다.
- 모든 시설 매핑을 검사하고, 특이한 형태·높이의 시설은 따로 시각 검수합니다. 확인하지 않은 부분은 완료라고 쓰지 않습니다.
- 최종 파일 위치, 부품 조립 방법, 공통 리그·소켓 규격, 동작 목록, 시설별 작업 지점, 검증 결과·남은 한계를 MD로 정리합니다.
- Unity에 적용할 사람이 파일을 받고 “가구에 붙어 있는 캐릭터를 떼어내야 하는” 작업을 하지 않아도 되게 만듭니다.

사용자에게는 핵심 변경과 실제 움직이는 결과를 먼저 보여 주세요. 모든 조합 검증이나 게임 적용을 했다고 과장하지 마세요.
