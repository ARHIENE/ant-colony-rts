# HUD V5 기능을 Unity 실제 게임에 구현하는 요청서

작성일: 2026-10-15 · 대상 프로젝트: `E:\Git\ant` · 개발 브랜치: `develop`

## 1. 작업 요청

현재 `design/hud/hud-v5.html`에 있는 관리 화면과 기능을 Unity 실제 게임에 구현해줘.

HTML을 다시 만드는 작업이 아니다. **Unity HUD에서 실제 장수·동물·건물·재고·작업·시간·저장 데이터를 조회하고, 유저의 지시가 실제 게임 행동으로 이어지게 하는 작업**이다. 기존 구현을 먼저 확인해서 이미 맞게 구현된 기능은 재사용하고, 화면만 있거나 기획과 다르게 동작하는 부분을 완성해줘.

범위는 최근 보완한 연구·농사·설비·장비·의료·귀환·추모뿐 아니라, V5에 먼저 추가한 물류·동물 위생·포로·원정 관리까지 포함한다. 아래 항목을 기능별로 나눠 진행하되 한두 화면을 추가한 상태를 전체 완료로 보고하지 마.

이번 문서는 구현 요청서다. 새로운 기획 결정, SAVE, 커밋·push, 컴퓨터 종료 요청을 포함하지 않는다.

## 2. 기준과 참조 자료

### 판단 우선순위

1. 사용자의 최신 확정 지시.
2. Notion의 최신 확정 기획. 페이지 안에서도 날짜와 폐기·대체 표시를 확인할 것.
3. HUD V5의 화면 구조·정보 구성·조작 흐름.
4. 기존 Unity 구현. 기획에 맞는 구현은 유지하고 재사용할 것.

**HTML의 고정 데이터·예시 수치·간략한 계산·강제 진행 버튼은 게임 규칙의 근거가 아니다.** HTML과 기획이 다르면 기획을 따르고 차이를 보고해줘. 상위 문서에 남은 구기획을 최신 분야별 확정안보다 우선하지 마.

## 3. 착수 방법과 공통 요구사항

1. `log.md`·공동 보드·현재 diff를 읽고 작업 중인 다른 변경을 보존한다. 보드의 과거 완료 표기보다 실제 코드를 확인한다.
2. Graphify로 관련 구현과 연결 관계를 찾는다. 기능별로 `구현됨 / 부분 구현 / 미구현 / 기획 불일치 / 결정 필요`를 분류하고 근거 파일을 적는다.
3. 공동 보드에 담당·수정 파일을 표시한다. 다른 담당자가 수정 중인 파일은 동시에 수정하지 않는다. 기존 보류 행을 새 구현 완료로 오인하지 않는다.
4. 기존 Unity UI·작업 스케줄러·재고 예약·의료·원정·저장 구조를 재사용한다. 화면마다 별도의 재고나 환자 상태를 만들지 않는다.
5. UI 조작은 실제 요청을 생성하고, 장수의 이동·작업·완료를 거쳐 상태가 바뀌어야 한다. 경로 불가·작업자 없음·재고 부족·시설 부족은 대기 사유로 표시한다.
6. 시간 진행은 기존 게임 시간에 연결한다. 배속과 일시정지를 반영하고 협상 페이지가 열려 있으면 관련 지역을 포함해 시간이 멈춘다.
7. 전체 우선순위는 높은 값 우선인 1~9, 기본 5. 작업 종류 금지는 0이다. 별도 미니 우선순위 체계를 만들지 않는다.
8. 예약·배송·소비·완료를 구분한다. 취소·사망·시설 철거·재지시·저장 불러오기에서 물자가 복제되거나 사라지지 않게 한다.
9. 기능별로 모듈화하고 Ponytail의 최소 구현 원칙을 적용한다. 관련 없는 리팩토링은 하지 않는다.

## 4. 구현 범위

### A. 연구

- 상단 과학 버튼과 관련 건물·명령에서 실제 연구 화면으로 진입.
- 소굴 → 증기 → 석유 → 전기 → 원자 → 미래의 6시대, 연구 설명·해금 효과·선행 조건·필요 자원·연구량·진행률 표시.
- 한 번에 하나의 연구를 진행하고 연구소별 장수 1명이 같은 연구에 기여. 같은 장수를 여러 연구소에 중복 배정하지 않음.
- 하위 등급 연구소는 상위 시대 연구에 기여하지 못함. 연구 기술·특성·연구소 보정은 기존 확정 규칙과 연결.
- 연구 지시·정지·재개·변경, 담당자 부재·시설 등급 부족·재료/설계도 부족 표시. 변경 시 진행 보존과 비용의 중복 차감 방지.
- 완료 후 다음 연구를 자동 선택하거나 반복하지 않음.
- HTML 예시 연구 몇 개만 덮어써 기존 연구 목록을 삭제하지 말 것. 연구소 승급 조건·새 연구 비용 등 미정 콘텐츠는 별도 확인.

### B. 농사

- 실제 밭을 선택해 작물·성장률·환경 조건·병충해·물주기·비료 허용·작업 우선순위·현재 지시를 확인/변경.
- 장수는 작업표에 따라 파종·수확·물주기 등을 수행하고 성장 중에는 다른 일을 함. 일반개미 보조를 되살리지 않음.
- 수확물은 현장 바닥에 생성되어 운반 작업으로 옮김.
- 최신 사용자 지시대로 **뿌리뽑기가 아니면 수확 후 심어진 상태로 재성장**. 뿌리뽑기는 확인 후 수행하고 빈 밭으로 남김. 오래된 재파종 설명과 충돌하면 최신 지시를 적용.
- 병충해는 상하좌우 연결 작물로 전파하고 대각선으로 전파하지 않음. 실제 밭 좌표로 판단하고 HTML의 3×3 예시 인덱스를 복사하지 않음.
- 성장 조건 불충족·재료 부족·접근 불가를 표시. 지시 취소·우선순위 변경도 실제 작업에 반영.
- 작물별 조건·산출·전파 주기 등 미정값은 확정값인 것처럼 만들지 않음. 스프링클러는 이번 필수 범위에 추가하지 않음.

### C. 전력·배관·자동화

- 실제 배치된 시설·전선·배관·신호선의 연결을 기반으로 관리 화면을 구성. 전역 체크박스 하나로 모든 건물의 연결 상태를 흉내 내지 않음.
- 전력망별 공급·수요·용량·연결 기계·사용 상태·중단 원인을 표시하고 기계 사용 중지/재개와 연결 변화가 실제 작동에 반영.
- 공급 단절·부족 등으로 망이 멈추면 **그 망에 연결된 기계들이 멈춤**. 임의로 우선순위를 만들어 일부 기계만 자동 선별하지 않음. 다른 독립 망까지 멈추지 않음.
- 냉장고·냉동고의 냉각/보존은 실제 전력 상태와 같은 데이터를 사용. UI와 물류에서 서로 다른 가동 상태를 갖지 않음.
- 배관·펌프·밸브·탱크의 실제 연결과 저장량/공급 상태 반영. 단절·밸브 닫힘·전력 없음 등의 원인 표시.
- 신호선은 전선·배관과 별개. 센서 입력·조건·논리 출력·제어 대상 표시. V5의 AND/OR/NOT 흐름을 연결하고 신호가 켜져도 다른 가동 조건이 부족하면 작동하지 않음.
- 건설 목록과 관련 관리 화면 연결. 철거·분리·재연결·저장 복원 시 연결망을 갱신.
- HTML의 공급 100, 전선 용량 140 같은 값은 예시다. 실제 용량·소모·과부하 결과·유체 처리 방식의 미정 사항은 먼저 묶어서 확인하고, 확정된 연결/상태/UI 부분은 진행.

### D. 장비

- 실제 장수의 무기·갑옷·장신구 슬롯과 실제 보유 장비 인스턴스를 표시.
- 장착·교체·해제 시 기존 장비의 행방을 보존. 품질·개체 식별·확정된 상태를 유지하고 중복 생성하지 않음.
- 무기 종류·전투 방식·장비 효과·날개 여부가 실제 장수와 전투에 반영.
- 원정 중인 장수가 본거지 보관함의 장비를 원격 장착하지 못하도록 접근 조건 적용.
- 반환/회수 장비는 자동 장착하지 않고 실제 물품으로 수령한 뒤 사용. 다른 장수의 장비를 자동으로 빼앗지 않음.
- 장비 내구도 등 HTML 표기와 실제 최신 기획의 충돌은 확인하고 임의로 새 시스템을 추가하지 않음.

### E. 장수 부상·질병·일반 의료

- 신체 부위: 머리(뇌), 눈 좌우, 더듬이 좌우, 큰턱 좌우, 가슴, 다리 6개, 배. 한 부위에 여러 상처·흉터가 남을 수 있고 상실/대체 부위를 구분.
- 통증·출혈·의식·이동·시력·감지·조작 등 상태와 해당 작업·전투 기능을 연결. 경상/중상 요약만으로 행동 가능 여부를 단순 결정하지 않음.
- 건강 화면에 부위별 상태·처치 여부·다음 처치 시간·질병 심각도/증상/면역·예상 출혈 사망 시간·치료 설정 표시.
- 일반 처치(약 없이 가능), 약품 처치/투약, 수술을 구분. 처치 완료와 완치를 구분하고 경과·회복이 실제 시간에 따라 진행.
- 약품 허용: 치료 안 함 / 약 없이 / 기초까지 / 일반까지 / 고급까지. 허용 범위 내 가장 좋은 재고를 사용하고 재고 없을 때 약이 필요한 처치는 시작 불가.
- 처치 품질은 의료 능력·사용 약품·시설·치료자 상태를 반영. HTML의 단순 성공률/품질 산식을 그대로 복사하지 않음.
- 자가 처치 조건과 품질 불이익, 의료 작업과 별도인 병상 휴식 우선순위 적용.
- 구조는 운반 가능한 장수, 처치·투약·수술·환자 급식은 의료 작업. 구조 목적지는 사용 가능한 의료 침상, 없으면 의료용 바닥 자리. 위급 출혈은 현장 처치 우선.
- 치료 중에도 장수는 배고픔이 진행. 스스로 먹지 못하면 의료 작업으로 급식. 치료·이동 중 질병/출혈 경과를 유지.
- 장수·동물 의료의 공통 우선순위: 생명 위험 → 중증 → 경증 → 대상 우선순위 → 거리 → 오래 기다린 요청. 진행 중 처치·수술은 완료 후 이동.
- 쓰러짐·위험 출혈·질병 위독·사망, 치료자/자리/약품 부족을 오른쪽 알림에 표시. 같은 문제는 갱신하고 클릭하면 대상 건강 화면으로 이동.
- 식중독·환경성 질병 등은 최신 기획의 회복 조건을 따름. 장수와 동물 사이 질병 전염은 없음.

### F. 장수 수술

- 시술 선택·대상 부위·필요 약품/재료/부품·집도의·대기 사유·진행·결과를 실제 수술 요청에 연결.
- 절단 등 되돌릴 수 없는 시술은 결과를 확인한 뒤 지시. 중상이라고 무조건 수술하지 않음.
- 의료용 침상과 필요한 물자가 있어야 시작. **의료용 바닥 자리에서는 수술 불가.** 출혈 처치 등 환자 조건도 확인.
- 준비 중 예약만 하고 시작 시 소비. 시작 전 취소는 예약 해제, 시작 후 취소 불가. 예약 상태와 보유 총량을 혼동하지 않음.
- 집도의 자동/직접 지정, 이탈 시 진행 정지·인계. 성공 판정은 실제 작업 기여도 가중 의료 능력을 사용하고 마지막 1% 작업자만 반영하지 않음.
- 실패 시 시술 미완료·추가 손상·사망 가능. 자동 재시도 없음. 실패 횟수 자체의 누적 벌점은 추가하지 않고 실제 남은 환자 상태로 재수술 가능 여부/위험 판단.
- 성공해도 회복 시간이 필요. 해당 시술의 목적만 해결하고 다른 부상·질병을 일괄 완치하지 않음.
- 흉터·상실은 일반 처치로 복구되지 않음. 대체 부위 설치/제거/교체는 해당 부위·물자·연구 조건을 적용.
- 부품 목록·성능·제조법·연구 조건은 미정. HUD의 검토용 대체 부품이나 ‘손상 복구’ 예시 시술을 확정 콘텐츠로 추가하지 말고 결정 필요 목록에 올릴 것.

### G. 동물 건강·위생·퇴비

- 기존 목장·동물 수술을 재사용하며 최신 완화된 의료 규칙에 맞춤. 폐기된 수술 실패 횟수/후유증 누적 벌점을 되살리지 않음.
- 동물 질병·전염성·부상·치료 상태와 치료 정책, 의료 장수 작업을 연결. 장수보다 완화된 관리 기준과 별도 동물 치료 시설 적용.
- 경상 자연 회복/목장 투약, 중상 수술, 시설 내 회복·복귀 대기, 환자 상태에 따른 재수술을 구분. 동물 수술의 완치 범위는 최신 동물 기획을 따르고 장수 수술 규칙을 무조건 공유하지 않음.
- 동물용 의약품·수술 키트는 구분. 의료 작업으로 제조하고 예약/소비를 실제 재고에 연결.
- 투약 효과는 투약 당시 경상만 대상. 이후 새 경상까지 기존 효과를 소급 적용하거나 연속 클릭으로 중복 소비하지 않음.
- 실제 동물이 배설물을 바닥 물품으로 남기며 기존 운반 방식으로 수거. 미수거 상태가 동물 건강 위험에 반영되고 정리하면 해당 원인이 해소.
- 퇴비통은 배설물·썩은 식품 허용, 우선순위, 원료 투입·숙성·꺼내기·완성 비료 반출을 처리. 가득 참/허용 해제/중도 반출 시 물량 보존.
- 일반 지역 전체의 오염·청결 시스템을 다시 추가하는 요청이 아님. 자동 도축도 추가하지 않음.

### H. 사망·묘비·추모

- 사망은 영구 처리. 활동 목록에서 제외하고 이름·날짜·원인 기록. 작업·미사용 예약·침대/시설 배정을 해제하며 다른 작업자가 인계할 진행도는 보존.
- 시신을 별도 운반 대상으로 남기고 미안치 시 부패 후 유해로 유지. 시신/유해와 장비는 별도 회수 대상.
- 실제 건설한 묘비 한 개에 한 구. 안치 지시→운반→안치, 꺼내기·이장, 시신이 남은 묘비 철거 금지.
- 시신을 못 찾으면 빈 묘비에 이름 등록, 이후 같은 묘비에 안치. 같은 고인의 묘비로 효과 중첩 금지.
- **장례식·사용자 추모 지시는 없음.** 지나가던 장수는 관계에 따라 추모하고 친한 장수는 여가에 방문. 전투·구조·응급 치료보다 우선하지 않음.
- 일시적 위로를 실제 기분 요인에 표시하고 중복/영구 누적 방지. 관계별 동료 사망·미안치 시신 목격의 기분 영향도 최신 기획대로 연결.
- 내 영토에서 사망하면 장비·운반 물자가 현장에 남고, 원정 등 내 영토 밖 사망/포획은 장비 압수. 귀환하지 않은 시신의 장비가 자동 복구되지 않음.
- 지휘관 사망 시 생존 병력은 자동 합류/즉시 인력 환급하지 않음. 후퇴·실제 귀환 및 결과 알림과 연결.

### I. 포로·외교·안전 귀환·압수 장비

- 실제 포로 목록·건강·급식·치료 정책·수용 상태·경비·탈출/제압·석방에 연결. 이동 불가 포로의 탈출은 금지.
- 몸값 반환과 상호 포로 교환. 제3자 포로 구매는 없음. 우리 장수 복귀 시 수용소/회유가 아니라 아군 복귀.
- 압수 장비는 장수 석방과 별도 조건. 상대 보관 정착지·소유자·품질/상태·반환 요구를 표시.
- 귀환 기간 = **게임 3개월 + 실제 거리 × 계수**. 거리 구간별 고정값이 아니라 연속 비례. 계수는 미정이며 기존 달력/시간 체계 사용.
- 기본 3개월은 1배속 실제 15분. 배속 적용, 일시정지/협상 중 정지. 협상 전에 귀환 예정일 표시, 성립 후 진행과 남은 시간 표시.
- 귀환 중 작업·전투·협상 참여 불가, 공격/재포획 없이 안전 귀환. 석방 당시 부상은 이동 중 회복하지 않고 도착 후 치료.
- **장수 석방과 함께 합의한 장비는 장수 귀환 때 함께 도착.** 일반 장비만의 거래는 즉시 수령. 받을 창고가 없으면 창고 주변 바닥 처리. 중복 도착/중복 차감 금지.
- 우리가 석방한 적 포로에도 같은 귀환 규칙을 적용.
- 대상의 사망·회유·이미 석방 등으로 보류 제안이 무효화되면 표시하고, 재진입 시 상황 변화 대사와 확인 버튼만 표시. 확인 후 제안/알림 종료. 대사 문구는 확정 아님.
- 점령으로 회수한 장비는 현지 물품이며 실제 수송이 필요. 소유권 변경 시 관련 협상의 유효성을 재검사.

### J. 원정·수송·지역 관리

- 실제 수송수단 선택, 조종사·승객·병력·포로·부상자·화물·목적지·정원·적재 상태를 표시.
- 승객 공간과 화물 용량 구분. 부상자/포로도 승객, 시신/유해는 화물. 물품의 실제 위치를 검사하고 다른 지역 물품을 원격 적재하지 않음.
- 준비·적재·취소·출발·이동·경로 변경·도착·지역 진입·하차/하역·철수·긴급 출발·수리를 실제 상태에 연결.
- 미탑승 인원/화물, 조종사 부재, 수리 필요, 정원 초과, 식량 부족 등을 표시하고 기획상 허용되는 위험 출발은 확인 후 처리.
- 이동 중 허용 식단과 적재 식품/약품을 사용. 처치·급식 가능, 수술 불가. 물품 상태와 탑승 인원 상태 보존.
- 본거지 자동 하역/하차 설정과 실제 도착 처리를 연결. 적재 취소만으로 실린 물품이 사라지지 않음.
- 수송수단 피탈·파괴·잔류 아군·점령지 상실 시 인원/물자의 행방을 기록. 시안의 강제 사고 버튼은 플레이 UI에 넣지 않음.
- 지역 전환 중에도 공통 시간과 현지 생활/위험 진행. 관련 알림과 선택 가능한 자동 일시정지 설정 적용.

### K. 기존 물류·식품·건설 UI의 남은 실제 연결

- 먼저 SPEC-1012 등의 기존 구현을 확인하고 중복 개발하지 않음.
- 창고별 허용 품목·실물 재고·우선순위·꺼내기/비우기·받을 곳 없음·운반 예약, 물량별 신선도·냉각 상태를 V5 화면에 연결.
- 보관한 물품은 바닥에 나오기 전까지 창고 우선순위 변경만으로 재배치하지 않음. 허용 해제는 바닥 배출. 최대 보관량 조절 기능은 추가하지 않음.
- 공통/장수별 식단, 복사/적용/공통 복귀, 레시피별 허용 재료, 생산 목록을 실제 식사·요리 작업에 연결.
- 정상 허용 식품 중 먼저 썩을 물량 사용, 썩은 식품은 정상 식품이 없을 때의 최후 선택 및 기분 영향. 질병은 최신 의료 기획과 연결.
- 식품 보존은 냉장고·냉동고 내부에만 적용하며 신선도를 복구하지 않음.
- 건설/개보수의 예약·배송·시작 소비, 취소·철거·이동과 바닥 반환, 일괄 요청/취소·개별 취소를 실제 작업 목록과 연결.
- 과거 로그의 식단·레시피 허용·요리 재료 원격 차감·냉각 저장 미완료 기록은 착수 시 다시 검증. 이미 다른 작업자가 고쳤다면 재사용.

## 5. 시안에서 그대로 복사하면 안 되는 부분

- 고정 장수 이름/ID, 고정 포로·묘비·연구소·수송대·밭 9칸, 예시 재고.
- `진행(시안)`, `상대 수락`, `피탈`, `부위 상실 예시`, `친구 관계 예시 설정` 등 상태를 강제로 만드는 버튼.
- 예시 몸값 80, 장비값 30, 거리 계수 0.08, 연구 비용/속도, 수술 성공률/회복 6시간, 위로 +4/1일 등의 값.
- 모든 상처의 기능을 단순히 `100 - 통증`으로 계산하는 방식, 모든 질병의 동일한 심각도/면역 경과.
- HTML 전역 배열 수정이나 화면 새로고침만으로 실제 이동·노동·재고 소비를 대체하는 방식.
- V5에 몇 가지 예시만 있다는 이유로 기존 게임 콘텐츠를 제거하거나 예시 목록을 최종 목록으로 확정하는 것.

미정 사항은 **한 번에 묶어서 질문**하고, 독립적으로 진행할 수 있는 확정 기능은 계속 구현해줘. 임시값이 필요하면 기존 설정을 우선 재사용하고 잠정값임을 명시하며, 게임 규칙을 바꾸는 중요한 결정은 임의 확정하지 마.

## 6. UI·디자인 요구사항

- 기존 Unity V5 UI 구조와 `DESIGN.md`, 제공된 디자인 스킬의 기준을 재사용. 새로운 테마로 재디자인하지 않음.
- 상태 → 가능한 조작 → 대기/불가 이유 순서로 읽히게 구성.
- 비활성 버튼은 이유를 알 수 있게 하고, 완료/실패/취소 후 정보가 즉시 갱신되게 함.
- 장수 상세·건물 상세·상단 메뉴·오른쪽 알림에서 같은 실제 대상에 접근. 화면별 데이터 불일치 금지.
- 목록이 길어도 스크롤·선택·초점을 보존. 한국어 텍스트 잘림·패널 밖 넘침·키보드 탐색 확인.
- 수술·방생·도축·긴급 출발 등 위험 동작의 확인 흐름은 해당 기획 유지.
- 아트 에셋 부재는 기존 UI/임시 시각물로 처리할 수 있으나 상태 변화 없는 가짜 버튼으로 기능을 대체하지 않음.

## 7. 저장·복원

- 새 상태는 실제 세이브에 저장하고 옛 저장에는 안전한 기본값/이관을 적용.
- 연구 진행/배정, 밭 작물/성장/병충해/지시, 설비 연결/설정, 장비 인스턴스/소유 상태를 복원.
- 부위별 상처·질병·면역·처치 시간, 약품/재료 예약, 수술 단계·집도의별 기여·회복 상태를 복원.
- 동물 질병·배설물·퇴비 원료/진행, 시신·묘비·추모 효과 만료, 포로 상태를 복원.
- 귀환 예정일·부상 스냅샷·동반 장비·지급 여부, 수송 승객/화물/경로/사고 상태를 복원.
- 복원 후 같은 물자를 다시 차감/생성하거나 이미 끝난 작업/알림을 재실행하지 않음. 삭제된 대상 참조와 예약을 정리.

## 8. 권장 작업 순서

1. 현황 대조표·담당 파일 확정, 기존 상태/저장 구조 확인.
2. 기존 시스템에 가까운 연구·장비·농사 및 물류 UI 연결.
3. 장수 의료 기반 → 수술 → 동물 의료/위생 → 사망/묘비/추모.
4. 포로·압수 장비·귀환 → 원정 수송·지역 연계.
5. 실제 설비 연결망·기계 가동·냉각 연결. 기존 기반이 있으면 앞 단계와 독립 진행 가능.
6. 단계별 저장 왕복·UI 동작·관련 회귀 검사 및 완료표 갱신.

범위가 크므로 기능별로 검증하되, 작업 순서는 실제 의존성을 보고 조정해도 된다. 아직 만들지 않은 영역은 완료 처리하지 마.

## 9. 검증 기준

Unity 공식 `unity` CLI와 `com.unity.pipeline`을 우선 사용. 기존 검사와 실제 Play 상태에서 확인하고 사용자 저장 데이터는 보호된 임시 경로와 구분한다. Unity 실행/저장 검사는 다른 담당자와 동시에 하지 않는다.

| 분야 | 반드시 확인할 대표 사례 |
| --- | --- |
| 연구 | 여러 연구소 공동 진행, 중복 장수 배정 방지, 선행/시대 차단, 중단/변경 보존, 완료 후 자동 선택 없음 |
| 농사 | 실제 장수 작업, 수확물 바닥 생성·재성장, 뿌리뽑기 후 빈 밭, 대각선 전파 없음, 환경/경로/재고 부족 |
| 설비 | 독립 망 분리, 연결/철거/재연결, 공급 부족·단절, 배관/밸브/신호선 구분, 냉장 상태 일치 |
| 장비 | 교체/해제 보존, 효과 변경, 중복 장착 금지, 원격 접근 차단, 저장 왕복 |
| 일반 의료 | 약 없는 처치, 허용 등급, 구조/급식, 새 상처, 흉터/상실 비복구, 의료/휴식 우선순위, 알림 이동 |
| 수술 | 약/재료 부족 차단, 바닥 수술 금지, 예약 취소 반환, 시작 후 소비/취소 금지, 집도의 교대·기여도, 성공·실패·사망·회복·재수술 |
| 동물 | 투약 당시 경상만 적용, 시설 안 새 경상, 질병 경과, 위생 수거·퇴비 물량 보존, 장수와 교차 감염 없음 |
| 사망/추모 | 예약/배정 해제, 장비 위치, 시신 부패/유해, 묘비 안치/꺼내기, 관계·여가 조건, 위로 중복/만료 |
| 귀환 | 거리 연속 비례, 예정일, 배속/정지/협상 정지, 부상 유지, 동반 장비 지연 도착, 단독 장비 즉시 거래, 중복 지급 없음 |
| 포로/협상 | 상호 교환, 사망/회유/이미 석방된 대상 무효, 확인 전용 화면, 적 포로 대칭 처리 |
| 수송 | 현지 적재, 정원/화물 구분, 긴급 철수 잔류, 하역 보존, 피탈/파괴, 이동 중 식사/의료 |
| 저장 | 준비/작업 중/중단/완료 직전의 저장 왕복, 옛 저장 이관, 참조 손실·물품 복제 방지 |

- 수술 성공률이 95%라고 성공한 실행에서만 검사하고 실패 시 건너뛰지 말 것. 성공·실패·사망 경로를 결정적으로 재현하여 각각 확인.
- 컴파일 통과만으로 완료하지 말 것. UI 조작 → 실제 요청 → 이동/작업 → 결과 → 저장 복원 흐름을 검증.
- 기존 `HudV5Unity`, `Spec1011Ranch`, `Spec1012`, `SaveRoundtrip` 등에서 변경 영향에 맞는 검사를 실행. 알려진 기존 실패는 원인/이번 변경 관련성을 구분.
- 테스트 기대값 변경은 기획 변경 근거가 있을 때만. 실패를 없애기 위해 검사 삭제/생략/성공 강제하지 말 것.
- SAVE 전 개발 일지·스크린샷/영상 캡처·커밋·push는 하지 않음. 검증은 캡처 없이 수행 가능.
