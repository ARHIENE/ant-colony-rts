# 생물형 적 전투 연결 — 2026-11-14

17종의 기존 모델·86클립을 웨이브 생성, 전투 행동과 저장 복원에 연결했다. Unity 사용을 기다리는 동안 `work/organic-combat-1114/code`에서 초안을 컴파일했고, 인계받은 뒤 실제 프로젝트에 적용했다. 신규 Meshy 생성은 하지 않았다.

## 연결한 행동

- 기존 표적 우선순위·NavMesh 이동을 유지하며 대기/이동/공격/피격/사망을 전환한다. 공격에는 준비 시간이 있고 피격이나 사거리 이탈로 취소할 수 있다.
- 근접형, 벽 파괴형, 원거리 투사체, 범위 공격, 벽 부식, 제한된 끌어당기기를 연결했다. 투사체는 발사자가 죽어도 진행하며 벽에 막힌다.
- 치유체는 제자리에서 회복을 준비하고 주변 아군 최대 6개체를 회복한다. 치유체끼리 무한 회복하거나 죽은 무리 구성원을 부활시키지 않는다.
- 운반체는 제한된 횟수로 새끼를 생성한다. 회수체는 생물형 시체를 소비해 회복한다. 보호형은 방향에 따른 피해 감소, 장막형은 주변 원거리 피해 감소를 제공한다.
- 굴착형은 기존 NavMesh를 따라 접근하고 잠시 지면 아래로 내려간다. 벽을 순간이동으로 통과하지 않으며 공격 대상으로 남는다.
- 첫 3웨이브 일반 적은 기본 근접형으로 제한한다. 이후 웨이브와 기존 표적 유형에 따라 종류를 선택한다. 기존 적 장수와 세력 습격은 유지한다.
- 종류·행동 단계·남은 시간·소환 횟수·투사체·부식·시체를 저장하고 복원한다. 기존 저장의 생물형 상태 누락은 일반 적으로 처리한다.

## 검증과 수정

`work/organic-combat-1114/combat-checks.txt`: **71검사 통과**. 17종 모델/Animator/동작별 월드 크기, 공격 준비·취소, 투사체·벽 차단·범위 공격, 부식, 끌어당김, 보호·장막·회복·소환·시체 소비, 실제 저장/불러오기, 실제 Update 이동·공격을 검사했다. 대부분은 조건을 구성한 기능 검사이며 자연 진행한 17종 전체 캠페인 검증은 아니다.

기존 `FunWaveSave1106Checks`로 첫 웨이브 15명과 적 장수 초기화·저장/복원 통과를 확인했다. 마지막 간격 수정 후 재실행은 CLI 30초 응답 타임아웃이 발생했다. 그 뒤 화면 검사에서는 생물형 14명+기존 장수 1명 상태와 20마리 무리(추가 인스턴스 19개)를 확인했다. 이 마지막 재실행 자체를 별도의 저장 검사 성공으로 세지 않는다.

실행 중 발견해 고친 문제:

- Unity의 파괴된 객체 비교 및 비활성 부모 아래 Animator 초기화 문제.
- JsonUtility가 null 생물형 상태를 종류 0 객체로 복원해 저장 검증이 거부되던 문제.
- FBX 단위 배율이 GPU 무리 복제에서 이중 적용되던 문제. BakeMesh 배율 처리를 바꾸고 실제 몸 크기 기준으로 간격을 조정했다.

최종 무리 몸 크기는 약 `(1.30, 0.85, 1.59)`이고 게임 화면에서 거대하게 늘어나는 현상이 사라졌다. 최종 컴파일 오류 0, 해당 Play의 콘솔 오류 0. 이전 RocketEconomy 오류는 콘솔 이력에 남아 있으며 이번 전투 검사에서 새로 발생한 것으로 처리하지 않았다.
