# 전투 연결 초안

상태: `code/` 아래 16개 C# 파일 작성. Unity와 같은 컴파일 응답 파일·참조 DLL을 사용한 독립 컴파일 종료0. 테스트 코드도 독립 컴파일 종료0. 아직 Assets 적용·Unity 실행 검증 전이다.

## 현재 구현한 초안

- 17종 안정 저장 ID, 이름/사거리/크기/공격 역할. 초기3웨이브는 근접형2종이며 기존 체력·피해량·인원 유지. 4~5웨이브10종, 6~7웨이브14종, 8웨이브부터17종 후보. 기존 적 장수·외교 침입은 유지한다.
- 단일 생물형 모델/Animator. 대기·이동·공격·피격·사망·치유 전환. 시체와 불러오기에서도 인간형 모델을 생성하지 않는다.
- 0.74초 공격 준비, 피격/사거리 이탈 취소, 실제 발사 후 비행. 조준 지점 회피, 벽 차단, 유한 범위 피해·갈고리 당기기·벽 부식.
- 충각수/돌파수 구조물 피해 배율, 사냥 기수 이동 속도, 치유체 살아 있는 아군 회복, 운반체2회×최대2개체 방출, 회수체 생물형 사체 소비, 정면 갑각 보호, 원거리 안개 보호, 잠복체 균열 예고·NavMesh 경로 이동·출현 대기.
- 무리 회복으로 사망한 몸체 수가 늘어나지 않음. 치유체끼리 회복하지 않고 대상별4초 중첩 잠금. 보호는 가장 강한 한 개만 적용하고 범위 공격은 우회한다.
- 발사자 사망 후에도 비행/부식 진행. 효과의 남은 시간과 대상, 적의 공격 준비·회복/안개·방출 횟수 저장. 구 저장 null은 기존 적으로 유지한다.

수치는 잠정이며 실제 웨이브 난이도 검증 완료를 뜻하지 않는다. 균열·회복 흐름·착탄 예고는 단순 선/도형 표시이고 최종 효과 아트가 아니다. 무리의 추가 몸체는 기존 GPU 정적 포즈 근사이며 개체별 스킨 리그로 확장하지 않는다.

## 적용 절차

생활 채팅의 Unity 반환을 먼저 확인한다. `apply_draft.py`는 현재 Assets의 SHA-256이 초안 시작 값과 모두 같은지 검사한 뒤 기존 파일을 before-combat에 백업한다. 불일치하면 중단하고 최신 파일에 필요한 부분만 재적용한다. 이 스크립트 자체는 Unity 사용권을 판단하지 않으므로 반환 전에 실행하지 않는다.

적용 후 공식 CLI로 컴파일 → `OrganicCombat1114Checks.cs`의 격리 새 게임 검증 및 실제 저장/로드 → 실제 이동·웨이브 생성과 화면 확인 → 사용자 설정/저장경로 복원·Play 종료 순서로 진행한다.
